# АГАТ — конфигурация 1С:Предприятие 8.3 (СЭД + оперативный учёт)

[![1С:Предприятие 8.3](https://img.shields.io/badge/1С-8.3.25%20(runtime%208.3.27)-yellow.svg)](https://1c.ru)
[![1C:EDT](https://img.shields.io/badge/IDE-1C%3AEDT-blue.svg)](https://edt.1c.ru)
[![Лицензия](https://img.shields.io/badge/Лицензия-Proprietary-lightgrey.svg)]()

**«АГАТ»** — конфигурация на платформе «1С:Предприятие 8.3» (разработка в 1C:EDT), объединяющая электронный документооборот, оперативный и складской учёт, управленческую бухгалтерию, расчёт заработной платы и планировщик задач.

Конфигурация написана «с нуля», **без библиотеки стандартных подсистем (БСП)**. Это ключевой факт для понимания структуры кода — см. раздел [Слой совместимости с БСП](#-слой-совместимости-с-бсп).

---

## 📦 Состав репозитория

| Каталог | Что это | Объём |
|---|---|---|
| `Agat/` | Конфигурация «АГАТ» | ~150 объектов метаданных, 110 модулей, ~34,5 тыс. строк BSL |
| `Agat.IIkona_ConnectorAI/` | Импортированная в EDT **оболочка** расширения ИИ | 11 файлов: `Configuration.mdo`, интерфейс команд, одна роль `Расш1_ОсновнаяРоль`. Модулей и прикладных объектов нет |

> ⚠️ `Agat.IIkona_ConnectorAI` — это **не исходники ИИ-подсистемы**. Функциональное расширение поставляется отдельным файлом `.cfe` и в репозитории не хранится. Подробнее — в разделе [Интеграция с ИИ](#-интеграция-с-ии).

Параметры конфигурации: режим управляемого приложения, русский вариант встроенного языка, режим совместимости **8.3.25**, целевой runtime **8.3.27**, управляемая блокировка данных, модальность не используется. Версия и поставщик конфигурации не заполнены.

## 📌 Функциональные подсистемы

В конфигурации 13 подсистем:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                            КОНФИГУРАЦИЯ «АГАТ»                               │
├────────────────────┬────────────────────┬────────────────┬───────────────────┤
│ 📁 Документооборот │ 📅 Планировщик     │ 💼 Учёт и склад│ 👥 Зарплата       │
│  • Договоры        │  • Диаграмма Ганта │  • Накладные   │  • Начисления     │
│  • Субподряд       │  • Задачи          │  • Списание    │  • Графики работы │
│  • Распоряжения ГД │  • Контроль сроков │    в произв-во │  • Регистр        │
│  • Распоряжения ТД │                    │  • Управленч.  │    расчёта        │
│  • Вх/Исх почта    │                    │    бухгалтерия │                   │
│  • ЛНА и служебные │                    │                │                   │
└────────────────────┴────────────────────┴────────────────┴───────────────────┘
```

### 1. 📁 Документооборот (СЭД)
* **Договорная работа:** `Договора`, `ДоговораСубподряда` — регистрация, этапы исполнения, контроль сроков, подбор исполнителей.
* **Распорядительные документы:** `РаспоряженияГД`, `РаспоряженияТД`, `ДокументыПриказыГД`.
* **Корреспонденция:** `ВходящиеДокументы`, `ИсходящиеДокументы`, `ВнутренниеДокументы`.
* **Локальные акты и служебные документы:** `ЛокальныеАкты`, `ДокументыУчредительныеДокументы`, `ДокументыКорпоративноеПраво`, `ДокументыДоверенности`, `ДокументыНедвижимоеИмущество`, `ДокументыПроекты`, `ДокументыРуководящиеДокументы`.
* **Связи между объектами:** 24 критерия отбора (`FilterCriteria`) — сквозная навигация «контрагент → его переписка / распоряжения / договоры», «сотрудник → его документы и этапы исполнения», «договор подряда → связанные документы».
* **Хранилище файлов:** файлы и сканы сохраняются **в каталог файловой системы**, путь к которому задаётся константой `ПутьХранилищаФайлов` (локальный или UNC-путь). Имя файла — GUID + расширение, в базе хранятся только ссылки. Регистр сведений `РегистрУдаленияФайлов` ведёт очередь на удаление. Это собственная реализация, а не механизм томов БСП.
* **Глобальный поиск:** обработчик `ГлобальныйПоискВДанных.ПриГлобальномПоиске` — поиск документов по номеру.

### 2. 📅 Планировщик задач
* Справочник `ЗадачиПланировщик`, общая форма `ЗадачиГрафик`.
* Визуализация сроков и этапов через элемент **диаграммы Ганта** (используется также в формах договоров и в отчёте `ОтчетИД`).

### 3. 📦 Оперативный, складской и бухгалтерский учёт
* Документы: `ПриходнаяНакладная`, `РасходПроизводство`, `ВводНачальныхОстатковНоменклатуры`.
* Регистры накопления: `ОстаткиМатериалов`, `СтоимостьМатериалов`, `Продажи`.
* План счетов `Основной` + регистр бухгалтерии `Управленческий` с поддержкой корреспонденции (двойной записи).
* Характеристики номенклатуры: план видов характеристик `СвойстваНоменклатуры`, регистр `ЗначенияСвойствНоменклатуры`, справочники `ВариантыНоменклатуры`, `ДополнительныеСвойстваНоменклатуры`.
* Регистр сведений `Цены`.

### 4. 👥 Кадровый учёт и расчёт заработной платы
* Справочники `Сотрудники`, `ВидыГрафиковРаботы`, регистр сведений `ГрафикиРаботы`.
* Документ `НачисленияСотрудникам`, план видов расчёта `ОсновныеНачисления`, регистр расчёта `Начисления`.

### 5. 🔄 Обмен данными
* `ExchangePlan.Отделения` — **распределённая информационная база (РИБ)**, `distributedInfoBase = true`.
* `ExchangePlan.Филиалы` — обычный план обмена (не РИБ).
* Обработки `ОбменДанными`, `ОбменСОтделениями`, общий модуль `Обмен`.

### 6. ⚙️ Регламентные задания
* `ОбновлениеИндекса` → `РегламентныеПроцедуры.ОбновлениеИндекса` (3 перезапуска при сбое с интервалом 10 с).

### 7. 📊 Отчёты
12 отчётов: `ОборотноСальдоваяВедомость`, `Материалы`, `РасходМатериалов`, `ОстаткиМатериаловПоСвойствам`, `НачисленияСотрудникам`, `ДиаграммаНачислений`, `Перерасчет`, `РейтингДоходов`, `РейтингУслуг`, `РеестрДокументовОказаниеУслуги`, `Универсальный`, `ИД`.

## 🤖 Интеграция с ИИ

Подсистема работы с языковыми моделями реализована **внешним расширением [ИИкона (1c-ai-connector)](https://github.com/andromanpro/1c-ai-connector)** и подключается к базе как `.cfe`.

**Что находится в этом репозитории, а что нет:**

| | |
|---|---|
| ✅ Есть | Слой совместимости с БСП в `Agat/src/CommonModules/`, без которого расширение не запускается |
| ✅ Есть | Оболочка проекта расширения (`Agat.IIkona_ConnectorAI`), импортированная в EDT — без прикладных объектов |
| ❌ Нет | Объекты `КИИ_*`: модели ИИ, эксперты, RAG, MCP-сервер, журнал запросов — они внутри `.cfe` |
| ❌ Нет | Вызовов ИИ-API из кода конфигурации: ни одной ссылки на `КИИ_` во всех 110 модулях |
| ❌ Нет | Ролей `КИИ_ПолныеПрава` / `КИИ_Пользователь` — они поставляются вместе с расширением |

Конфигурация **не вызывает** ИИ-функции напрямую. Вся ИИ-логика живёт в расширении и обращается к конфигурации только через модули-адаптеры (см. следующий раздел). Описание провайдеров, экспертов, агентской петли, RAG и MCP, а также сигнатуры программного API — в документации вышестоящего проекта:

* **Репозиторий:** [andromanpro/1c-ai-connector](https://github.com/andromanpro/1c-ai-connector)
* **Руководство пользователя:** [andromanpro/1c-ai-connector-guide](https://github.com/andromanpro/1c-ai-connector-guide)

## 🧩 Слой совместимости с БСП

Расширение ИИконы рассчитано на конфигурацию с БСП. «АГАТ» построен без неё, поэтому в конфигурацию добавлен набор модулей-адаптеров, повторяющих сигнатуры вызываемых методов БСП:

| Модуль | Назначение |
|---|---|
| `ОбщегоНазначения`, `ОбщегоНазначенияКлиент`, `ОбщегоНазначенияКлиентСервер` | Реквизиты объектов, работа со структурами и массивами, JSON, хранилище настроек, «безопасное хранилище» |
| `ДлительныеОперации`, `ДлительныеОперацииКлиент`, `ДлительныеОперацииКлиентСервер` | Запуск фоновых заданий и опрос их состояния |
| `ФайловаяСистема`, `ФайловаяСистемаКлиент`, `ФайловаяСистемаКлиентСервер` | Помещение и получение файлов |
| `СтандартныеПодсистемыКлиент`, `СтандартныеПодсистемыСервер` | Параметры работы клиента, «версия библиотеки» |
| `Пользователи`, `ПользователиКлиентСервер` | Текущий и авторизованный пользователь, признак администратора |
| `СтроковыеФункцииКлиентСервер` | Подстановка параметров в строку, транслитерация |

Это **эмуляция подмножества БСП, а не БСП**. Реализация писалась под конкретные вызовы расширения и покрывает только их. Часть методов продублирована под несколькими именами (`ЗначениеИзJSON`, `ЗначениеИзСтрокиJSON`, `JSONВЗначение`, `JSONВСтруктуру`, `СтрокаJSONВЗначение`, `СтрокаJSONВСтруктуру` — один и тот же разбор JSON), потому что имена подбирались под фактические вызовы из `.cfe`.

Собственные прикладные общие модули конфигурации: `РаботаСДокументами`, `РаботаСоСправочниками`, `РаботаСФайламиКлиент`, `РаботаСФайламиСервер`, `ПроведениеРасчетов`, `Обмен`, `ЗагрузкаДанныхСервер`, `РегламентныеПроцедуры`, `ГлобальныйПоискВДанных`, `ВременноеХранилище`.

## 🔒 Ролевая модель

В конфигурации 12 ролей:

| | | |
|---|---|---|
| `Администратор` | `ДоговорнойОтдел` | `Производство` |
| `Бухгалтер` | `Канцелярия` | `ПроизводствоИсполнитель` |

## 🚀 Развёртывание

### 1. Открытие проекта в 1C:EDT
```bash
git clone https://github.com/santonov62/1c-agat.git
```
1. Импортируйте в рабочее пространство 1C:EDT проекты `Agat` и `Agat.IIkona_ConnectorAI`.
2. Настройте привязку проекта `Agat` к информационной базе.

> ⚠️ Перед первой сборкой ознакомьтесь с разделом [Известные проблемы](#-известные-проблемы) — в текущем состоянии ветки `dev` конфигурация не компилируется.

### 2. Настройка хранилища файлов
Заполните константу `ПутьХранилищаФайлов` — каталог, доступный серверу 1С на запись.

### 3. Подключение расширения ИИ
1. Подключите файл расширения ИИконы (`.cfe`) к информационной базе.
2. В режиме «1С:Предприятие» откройте раздел **«Коннектор ИИ» ➔ «Модели ИИ»** и нажмите **«Заполнить модели»**.
3. Откройте нужную модель, укажите API-ключ, сохраните.
4. Проверьте работу через **«Коннектор ИИ» ➔ «Сервис» ➔ «Тест ИИ»**.

## ⚠️ Известные проблемы

Состояние ветки `dev`. Проблемы подтверждены валидацией 1C:EDT и чтением исходников.

### Блокирующие

1. **Синтаксическая ошибка — конфигурация не компилируется.**
   `Agat/src/CommonModules/ДлительныеОперации/Module.bsl:78`:
   ```bsl
   Модуль[Части[1]](ПараметрыПроцедуры, АдресРезультата);   // недопустимая конструкция BSL
   ```
   Обращение к методу модуля по индексу во встроенном языке не поддерживается. EDT выдаёт по файлу каскад из 5 синтаксических диагностик. Требуется замена на `Выполнить(...)`.

2. **`Переменная 'Обмен' не определена`** — 7 модулей объектов: `ВариантыНоменклатуры`, `ДополнительныеСвойстваНоменклатуры`, `Контрагенты`, `Номенклатура`, `Склад`, `Сотрудники`, `ChartsOfCharacteristicTypes.СвойстваНоменклатуры`. Один и тот же скопированный обработчик.

3. **Несуществующий метод платформы:** `ФайловаяСистемаКлиент` вызывает `ПоместитьФайлВХранилищеАсинх` — такой функции нет ни в одном клиентском приложении.

4. **Методы, недоступные в веб-клиенте:** `ЗаписатьJSON` / `ПрочитатьJSON` в `ОбщегоНазначенияКлиентСервер`, `ОткрытьЗначение` в `РаботаСФайламиКлиент`.

### Безопасность

5. **API-ключи LLM хранятся в открытом виде.** «Безопасное хранилище» в `ОбщегоНазначения` — обёртка над `ХранилищеОбщихНастроек`:
   ```bsl
   ХранилищеОбщихНастроек.Сохранить("БезопасноеХранилищеДанных", Строка(Ключ), Данные);
   ```
   Ключ доступен любому пользователю с правом чтения хранилища общих настроек. В БСП для этого используется отдельный регистр с привилегированным доступом.

6. **Подавление ошибок.** ~215 блоков `Попытка` на 34,5 тыс. строк, из них 12 с полностью пустым `Исключение`, при 28 вызовах `ЗаписьЖурналаРегистрации` на весь проект. Сбой записи API-ключа проходит незамеченным.

### Качество кода

7. **29% BSL-кода — точные копии.** 36 файлов дублируются байт в байт (10 061 строка): 7 идентичных `ФормаСписка` по 927 строк, 7 идентичных `ФормаЭлемента`, 7 идентичных `ФормаПодбораИсполнителей`, 12+ идентичных `ObjectModule.bsl`. Правка логики требует синхронного изменения в семи местах; проблема №2 — прямое следствие.

8. **`CommonForms/ОтчетИД/Module.bsl` — 8 263 строки**, четверть всего кода проекта в одном модуле.

9. **Именование:** 45 общих картинок с именами вида `картинка_1`, `Картинка_4`, `ОбщаяКартинка1`.

10. **Не настроены проверки `v8codestyle`** для проекта `Agat` (в проекте расширения — настроены).
